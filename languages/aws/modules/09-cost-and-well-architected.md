# Cost & Well-Architected

**Course:** AWS Cloud Course (donor / allowlist access)  
**Module:** 9 of 10

## Learning goals

By the end of this lesson you will be able to:

- Use tags and Cost Explorer categories
- Name the Well-Architected pillars at a high level
- Apply one cost-saving action (stop/rightsize/lifecycle)

## Why this matters

Cloud cost is an architecture problem. Well-Architected gives a vocabulary for trade-offs.

## Core ideas

1. **Cost visibility** before optimisation.
2. **Rightsizing & scheduling** — stop learning boxes overnight.
3. **Pillars** — operational excellence, security, reliability, performance, cost, sustainability.
4. **Questions over dogma** — WA is a review lens.

## Worked example

### Lab: $0-ish cleanup hunt

1. Open Cost Explorer (or billing).
2. List running resources with tags.
3. Stop/terminate abandoned labs.
4. Write one Well-Architected question you would ask your design (e.g. “How do we recover from AZ loss?”).


## Practice

1. Tag all lab resources consistently.
2. Perform one cleanup that reduces idle cost.
3. Answer two WA questions for your sample app in writing.

## Common mistakes

- Optimising before measuring
- Orphaned Elastic IPs / idle NAT / forgotten disks
- Treating WA as paperwork only
