# Capstone: ship a small service

**Course:** DevOps Foundations Course (donor / allowlist access)  
**Module:** 10 of 10

## Learning goals

By the end of this lesson you will be able to:

- Ship a small service with CI, container, and a release note
- Demonstrate rollback and a basic dashboard/alert idea
- Present your path as a portfolio story

## Why this matters

Capstones prove you can connect habits end-to-end — the skill employers and teams actually need.

## Core ideas

1. **Thin vertical slice** — one endpoint, real pipeline, real notes.
2. **Evidence pack** — repo link, pipeline screenshot, runbook, metrics note.
3. **Honest limits** — say what you did not automate yet.

## Worked example

### Capstone definition of done

- [ ] Repo with README + `.env.example`
- [ ] CI runs tests on PR
- [ ] Docker image builds with a version tag
- [ ] Compose or cloud deploy path documented
- [ ] Release checklist + rollback
- [ ] One structured log or metric + one alert idea
- [ ] 5-minute demo script


## Practice

1. Complete the definition of done for your sample service.
2. Record a 5-minute walkthrough (or written script).
3. List three improvements for a “v2” backlog.

## Common mistakes

- Over-scoping (microservices mesh on day one)
- No evidence artefacts — only claims
- Skipping rollback practice

## Stretch goal

Add a canary or feature flag to the demo story.
